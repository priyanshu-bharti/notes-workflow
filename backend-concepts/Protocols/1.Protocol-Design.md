## Protocol Design

### What is a protocol?

- A protocol is a set of rules that enables two or more parties to communicate effectively.
- When designing a protocol, several properties must be considered to ensure it meets its intended purpose.
- These properties include data format, transfer mode, addressing system, statefulness, routing, flow and congestion control, and error management.

### Protocol Properties

- Data Format: Format of the actual data being exchanged is very crucial.
  - Text Based (plaintext, JSON, XML)
  - Binary (Protobuf, RESP (Redis Serialization Protocol), HTTP/2, HTTP/3)
- Transfer Mode: What mechanism are you using to transfer the data.
  - Message Based (UDP, HTTP) (Clearly defined start and end)
  - Stream (TCP, WebRTC, Websockets) (Defines start but not the end)
- Addressing System: Where is it coming from and going to?
  - DNS Name, IP Address, MAC Address
- Stateful vs Stateless
  - Stateful: Maintains a connection state (TCP)
  - Stateless: Doesn't maintain a connection state (HTTP)
- Routing: How to figure out where to go?
  - Proxies, Gateways
- Flow and Congestion Control: (Is the connection reliable or not?)
  - UDP doesn't have any controls.
  - TCP has built in flow and congestion control.
- Error Management
  - Error Code.
  - Timeouts and Retry Mechanisms.
