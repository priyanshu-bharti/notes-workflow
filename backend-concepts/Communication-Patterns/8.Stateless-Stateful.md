## 🧠 Stateful vs Stateless Backends

### Stateful Backends

- Maintains client-specific state in memory across multiple requests.
- Depends on session data (e.g., user login info, cart contents).
- Restarting or scaling requires session persistence or sticky sessions (e.g., same server handles same client).

### Stateless Backend

- Does not retain any client state between requests.
- Each request must contain all the context the server needs (e.g., authentication token, data).
- Easier to scale and restart since no in-memory state is assumed.

### ️Can Stateless Backends Store State?

- Yes. Stateless backends can store data, but they don’t rely on in-memory state:
  - Data is externalized (e.g., in databases, caches, object storage).
  - Clients are responsible for sending necessary context with each request (e.g., JWT tokens, session IDs).
    - A stateless backend can be restarted during idle time without breaking ongoing client workflows — as long as the client includes all needed info in each request.

### What Makes a Backend "Stateless"?

- The backend logic does not depend on prior interactions.
- Even if the system is stateful (e.g., user data in a DB), the backend remains stateless if it doesn’t store session info in memory.
- Statelessness applies to backend behavior, not the absence of data in the system.

## Protocols: Stateless vs Stateful

### Examples:

| Protocol        | Type            | Reason/Behavior                                                        |
| --------------- | --------------- | ---------------------------------------------------------------------- |
| TCP             | Stateful        | Maintains connection state (sequence numbers, ACKs, file descriptors). |
| UDP             | Stateless       | No connection state; each packet is independent.                       |
| DNS (over UDP)  | Stateless       | Uses a `queryId` to match requests with responses.                     |
| QUIC (over UDP) | Pseudo-Stateful | Implements connection IDs to maintain continuity over stateless UDP.   |
